# 索引设计

## 1. 设计原则

索引优先服务实体唯一定位、外键约束和核心组合查询。按项目 MySQL 8 技术栈的索引目标设计，主键与唯一约束会形成索引，因此不再设计相同字段或相同前缀的普通索引；基础表数据量小，不为名称、说明、单位或坐标堆叠低收益索引。本页是索引方案，不表示索引已创建；整体 DDL 实施仍应遵循完整性约束文档确定的 MySQL 8.0.16+ 最低版本。

## 2. 索引清单

| 表 | 索引名 | 类型 | 字段顺序 | 用途 |
| --- | --- | --- | --- | --- |
| `city` | `PRIMARY` | 主键索引 | `(id)` | 按主键定位城市，供外键引用。 |
| `city` | `uq_city_city_code` | 唯一索引 | `(city_code)` | 城市编码判重与编码查询。 |
| `forecast_model` | `PRIMARY` | 主键索引 | `(id)` | 按主键定位模型，供外键引用。 |
| `forecast_model` | `uq_forecast_model_model_code` | 唯一索引 | `(model_code)` | 模型编码判重与编码查询。 |
| `weather_element` | `PRIMARY` | 主键索引 | `(id)` | 按主键定位要素，供外键引用。 |
| `weather_element` | `uq_weather_element_element_code` | 唯一索引 | `(element_code)` | 要素编码判重与编码查询。 |
| `forecast_record` | `PRIMARY` | 主键索引 | `(id)` | 按主键定位预报记录。 |
| `forecast_record` | `uq_forecast_record_business` | 组合唯一索引 | `(city_id, model_id, element_id, forecast_time)` | 业务判重，并服务城市、模型、要素等值过滤后的有效时间范围查询。 |
| `forecast_record` | `idx_forecast_record_model_id` | 普通索引 | `(model_id)` | 支持模型外键检查、按模型关联和引用检查。 |
| `forecast_record` | `idx_forecast_record_element_id` | 普通索引 | `(element_id)` | 支持要素外键检查、按要素关联和引用检查。 |

## 3. 组合索引与查询匹配

核心查询固定以 `city_id`、`model_id`、`element_id` 进行等值筛选，再对 `forecast_time` 使用范围条件并按时间读取。因此 `uq_forecast_record_business(city_id, model_id, element_id, forecast_time)` 的字段顺序与查询条件完全匹配：前三列缩小业务组合，末列支持有效时间范围扫描。该唯一索引同时承担判重和查询职责，无需再建立字段完全相同的普通组合索引。

按照最左前缀规则，该组合唯一索引还能支持以 `city_id` 开头的访问路径，因此不再创建单列 `city_id` 索引。`model_id` 与 `element_id` 不是该索引的最左列，为确保外键引用检查和相应连接有明确可用的访问路径，分别保留单列索引 `idx_forecast_record_model_id` 与 `idx_forecast_record_element_id`。

## 4. 避免重复与暂不建立的索引

- 不另建 `city(city_code)`、`forecast_model(model_code)`、`weather_element(element_code)` 普通索引，因为对应唯一索引已覆盖。
- 不另建 `forecast_record(city_id)`，因为组合唯一索引以 `city_id` 为最左列。
- 不另建与 `uq_forecast_record_business` 同字段的查询索引。
- 暂不为 `forecast_time` 单独建索引，因为当前查询要求同时指定城市、模型和要素；若后续经真实执行计划证明存在跨实体的纯时间查询，再单独评估。
- 暂不为基础表名称、`description`、`unit`、经纬度或 `value` 建索引，当前范围没有以这些字段进行高频定位或排序的需求。

## 5. 验证与维护

下一阶段形成 SQL 详细设计后，应在 MySQL 8.0.16+ 目标实例上使用核心查询条件检查执行计划，确认组合唯一索引用于前三列等值与末列范围访问；同时检查未因外键自动生成与显式索引重复的索引。只有在演示数据规模和实际查询计划证明有收益时才调整索引，且调整后必须同步逻辑结构、数据字典和完整性约束说明。
