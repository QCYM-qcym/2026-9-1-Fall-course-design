# 数据库需求分析

## 1. 设计目标与范围

数据库用于保存课程演示所需的江苏省城市、预报模型、气象要素和预报记录，为按城市、模型、要素及有效时间范围查询，以及表格、温度折线图和降水柱状图提供统一数据来源。项目技术栈总称保持为 MySQL 8；由于本设计依赖城市经纬度 `CHECK` 约束实际执行，目标数据库实例的最低版本固定为 MySQL 8.0.16+。MySQL 8.0.15 及以下版本不能作为依赖该 `CHECK` 约束的部署目标。本阶段只形成结构与约束基线，不执行建库或建表。

设计范围固定为 `city`、`forecast_model`、`weather_element`、`forecast_record` 四张表，不增加用户、权限、日志、数据源或审计字段。数据来自人工构造的课程演示资料，不接入实时预报资料、NetCDF、ERA5 或其他在线数据。

上游数据需求中的“演示数据说明”、气象要素补充说明及必要的生成、更新信息，由演示数据配套说明材料维护，不扩展为本阶段的表或字段。数据库内的要素识别与展示信息固定由 `element_code`、`element_name` 和 `unit` 承担。

## 2. 数据对象

| 实体 | 数据职责 | 关键标识 | 主要业务用途 |
| --- | --- | --- | --- |
| 城市 `city` | 保存可查询城市及其地理位置。 | 主键 `id`；唯一编码 `city_code` | 限定江苏省演示城市，支持城市筛选和可选地图定位。 |
| 预报模型 `forecast_model` | 保存预报模型基础资料。 | 主键 `id`；唯一编码 `model_code` | 支持 ECMWF、NOAA 等模型筛选。 |
| 气象要素 `weather_element` | 保存要素名称和展示单位。 | 主键 `id`；唯一编码 `element_code` | 区分 T2M（℃）与 PRECIP（mm），保证展示单位明确。 |
| 预报记录 `forecast_record` | 保存某一业务组合在某一有效时间的预报值。 | 主键 `id`；组合唯一键 `(city_id, model_id, element_id, forecast_time)` | 作为查询表格与图表的共同明细数据源。 |

## 3. 记录粒度与关系

一条 `forecast_record` 精确表达“某城市、某预报模型、某气象要素在某有效时间的一个预报数值”。`forecast_time` 表示预报值对应的有效时间，不扩展其他时间字段。

三个基础实体分别与预报记录形成 1:N 关系：

- 一个 `city` 可以关联零条或多条 `forecast_record`，每条预报记录必须且只能关联一个城市。
- 一个 `forecast_model` 可以关联零条或多条 `forecast_record`，每条预报记录必须且只能关联一个预报模型。
- 一个 `weather_element` 可以关联零条或多条 `forecast_record`，每条预报记录必须且只能关联一个气象要素。

主键用于稳定标识单条数据，三个外键保证预报记录引用的基础资料真实存在。被预报记录引用的基础资料不得直接删除，以免形成孤立记录。

## 4. 查询与维护需求

核心查询同时使用城市、预报模型、气象要素和有效时间范围过滤 `forecast_record`，结果按有效时间供表格和图表使用。T2M 数据以 ℃ 展示并绘制折线图，PRECIP 数据以 mm 展示并绘制柱状图；单位从 `weather_element.unit` 取得，不在预报记录中重复保存。

基础数据管理仅维护四类既定对象。新增预报记录时，必须验证三个关联对象存在、有效时间和值非空，并拒绝与既有 `(city_id, model_id, element_id, forecast_time)` 重复的数据。修改时也不得产生重复业务组合；删除基础资料前必须检查引用关系。

## 5. 数据质量与边界

- 所有编码字段唯一且非空，所有名称字段非空。
- 城市经度、纬度非空，并分别满足 `-180 ≤ longitude ≤ 180`、`-90 ≤ latitude ≤ 90`。
- `weather_element.unit` 非空，保证表格和图表能够明确展示单位。
- `forecast_record` 的三个外键、`forecast_time` 与 `value` 均非空。
- T2M 与 PRECIP 的合理数值范围不同，由业务层结合 `element_code` 验证；数据库不设置无法同时正确表达两类要素的通用 `value` 数值检查。
- 演示数据至少覆盖一个江苏城市、ECMWF、NOAA、T2M、PRECIP，以及正常查询、无结果查询和管理校验场景。
