# 核心课程设计资料实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立 25 份相互链接的核心课程设计文档和 10 张可直接在 Obsidian 中打开的 Canvas 白板。

**Architecture:** 所有成果位于当前 Vault 的 `课程设计/` 下，以项目导航为总入口，需求、系统设计、数据库设计和项目管理四组文档构成知识主干。Canvas 使用原生 JSON Canvas 格式，图与对应说明文档互相链接；最终通过结构、JSON、ID、重叠、链接和范围检查完成验收。

**Tech Stack:** Markdown、Obsidian Wikilink、JSON Canvas、MySQL 8 数据建模说明

**Spec:** `课程设计/00-项目总览/文档体系实施设计.md`

## Global Constraints

- 项目规模固定为 2 人、约 2 周。
- 本轮只创建文档与 Obsidian Canvas，不创建 Spring Boot、Vue、MySQL 实例或业务代码。
- 技术栈冻结为 Vue 3、Vite、JavaScript、Element Plus、ECharts、Axios、Vue Router、Java 8、Spring Boot 2.7.18、MyBatis-Plus、Maven、MySQL 8。
- 核心气象要素仅为 `T2M` 和 `PRECIP`；`ECMWF`、`NOAA` 作为示例预报模型。
- 核心数据库只包含 `city`、`forecast_model`、`weather_element`、`forecast_record`。
- 江苏地图为增强功能，不进入核心验收承诺。
- 未开发能力使用“计划实现”“拟采用”等表述，不得写成“已实现”。
- TDengine、ERA5、NetCDF 在线解析、RMSE、登录权限、微服务和生产部署只允许作为扩展方向提及。
- Markdown 链接使用含目录的 Wikilink，Canvas 必须包含顶层 `nodes` 与 `edges` 数组。
- 当前目录不是 Git 仓库，因此本计划不包含 Git 提交步骤。

### Task 4: 编写数据库设计文档

**Files:**
- Create: `课程设计/03-数据库设计/01-数据库需求分析.md`
- Create: `课程设计/03-数据库设计/02-ER模型设计.md`
- Create: `课程设计/03-数据库设计/03-逻辑结构设计.md`
- Create: `课程设计/03-数据库设计/04-3NF规范化分析.md`
- Create: `课程设计/03-数据库设计/05-数据字典.md`
- Create: `课程设计/03-数据库设计/06-完整性约束设计.md`
- Create: `课程设计/03-数据库设计/07-索引设计.md`

**Interfaces:**
- Consumes: Task 2 的数据需求。
- Produces: ER 图、关系模型图和下一阶段 SQL 详细设计的基线。

- [ ] **Step 1: 编写数据库需求与 ER 模型**

  明确四个实体、三条 1:N 关系、记录粒度，以及 PK/FK 的作用；不增加用户、权限、日志或数据源表。

- [ ] **Step 2: 固化逻辑结构**

  为四张表定义 MySQL 8 候选字段类型、主键、外键、唯一约束和非空约束。`forecast_record` 使用 `(city_id, model_id, element_id, forecast_time)` 组合唯一约束，防止同一组合重复记录。

- [ ] **Step 3: 完成 3NF 分析**

  分别说明每张表的一范式、二范式、三范式依据，明确不在 `forecast_record` 冗余保存 `city_name`、`model_name`、`element_name` 和 `unit`。

- [ ] **Step 4: 编写数据字典**

  逐字段说明名称、类型、可空性、键、默认值或约束、业务含义和示例。经纬度使用 `DECIMAL`；数值记录使用 `DECIMAL`；时间使用 `DATETIME`。

- [ ] **Step 5: 编写完整性约束**

  覆盖实体完整性、参照完整性、唯一性、非空、数值边界和删除策略；建议基础数据被引用时限制删除，修改通过业务层验证。

- [ ] **Step 6: 编写索引设计**

  保留主键、唯一索引和外键索引，并设计服务于城市、模型、要素、时间范围组合查询的复合索引；说明索引顺序与查询条件匹配关系，避免为小表堆叠重复索引。

- [ ] **Step 7: 检查跨文档字段一致性**

  对照数据字典、关系模型和 ER 图，确保表名、字段名、PK/FK、基数和唯一约束完全一致。
