# 非功能需求 V2

以下是待执行验收标准，不是实测结果。

## 1. 易用性（NFR-U）

- NFR-U-01：四页导航清晰；不同页面只显示需要的筛选条件，标题、时刻、模型、要素、单位明确。
- NFR-U-02：深色现代气象工作台，地图最大，悬浮半透明卡片、适量模糊、8～12px 圆角、统一控件尺寸；动画 200～300ms，不大量堆叠边框。
- NFR-U-03：Loading overlay、Empty、Error（ElMessage 与重试）、CRUD Success（ElMessage.success）全部具备；错误不能显示为成功或空结果。

## 2. 正确性（NFR-C）

- NFR-C-01：同轮响应驱动地图/详情，趋势表格/双图/统计；℃ 与 mm 不混用。无值显示“暂无数据”，图上断点，不补零。
- NFR-C-02：时间、关联、数值、唯一性按 API V2 校验；快速切换只接受最新请求响应，不让旧响应覆盖新筛选。
- NFR-C-03：修改数据后缓存失效，重新查询可验证新值；累计降水的来源和缺测说明可见。

## 3. 可维护性（NFR-M）

- NFR-M-01：四页面、五 Controller、五 Service、四 Mapper、四表；基础 CRUD 复用标准逻辑，展示查询集中 XML。
- NFR-M-02：冻结技术栈、统一 API DTO/VO，前后端分目录，文档唯一来源在课程设计/；不加无必要依赖。

## 4. 兼容性（NFR-K）

- NFR-K-01：未来分别在 Chrome、Edge 完成最终 Demo，并检查地图、时间轴、双图、双模型及四 Tab 无阻断错误。
- NFR-K-02：以桌面 1366×768 与 1920×1080 检查，地图、图例、时间轴与详情不遮挡；窄窗口可折叠详情，不承诺移动端适配。

## 5. 安全边界（NFR-S）

- NFR-S-01：非法时间/关联/非有限数值、负降水返回正确错误且不写库；SQL 参数绑定，不拼接用户输入；不把数据库异常栈返回页面。
- NFR-S-02：无登录、权限或生产级安全体系，限课程演示；密码通过环境/本地配置管理，禁止写入文档。

## 6. 可演示性与流畅度（NFR-D）

- NFR-D-01：计划 16×2×2×56 数据，济南/青岛覆盖完整序列；明确演示来源与时间窗口。
- NFR-D-02：中检先交付地图主链路，最终交付全部四页；不承诺高并发或高可用。
- NFR-D-03：浏览器 Network 验证首次批量查询后连续拖动时间轴至少 10 次，新增 API 请求为 0；切回相同缓存键无需重复请求；CRUD 后必须重新请求。记录机器、数据量及观察结果，不捏造延迟数值。
