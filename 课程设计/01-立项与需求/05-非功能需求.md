# 非功能需求

## 1. 易用性（NFR-U）

- NFR-U-01：查询区应清楚标识城市、日期/时间范围、气象要素和模型四个条件。
- NFR-U-02：表格、温度折线图和降水柱状图应有标题、单位和空结果提示。验收时，由未参与开发的课程演示人员仅依据页面字段名称，依次选择城市、日期/时间范围、气象要素和预报模型完成 T2M、PRECIP 与无匹配记录三次查询；四项条件均可定位，T2M 结果的表格和折线图均显示标题及 ℃ 单位，PRECIP 结果的表格和柱状图均显示标题及 mm 单位，无匹配记录时显示空结果提示，且无需他人解释字段含义，即判定通过。

## 2. 正确性（NFR-C）

- NFR-C-01：同一轮查询中表格与图表使用同一组结果，T2M 显示单位为 ℃，PRECIP 显示单位为 mm。
- NFR-C-02：预报记录保存和查询时应校验城市、模型、要素关联存在，时间范围起止合法。

## 3. 可维护性（NFR-M）

- NFR-M-01：查询、可视化和基础管理边界清晰，城市、模型、要素、预报记录采用独立的数据对象管理。
- NFR-M-02：技术实现固定采用 Vue 3 与 Spring Boot 2.7.18 等已冻结技术栈；新增核心要素或模型时不应改变既有记录的含义。

## 4. 兼容性（NFR-K）

- NFR-K-01：课程演示环境应分别使用 Chrome 和 Microsoft Edge 各完成一次核心流程验收：设置四项查询条件、提交查询、查看结果表格、查看 T2M 温度折线图与 PRECIP 降水柱状图，并另以无匹配条件查询一次。两种浏览器中字段可操作、表格和两类图表均可见且可渲染、每项图表具有对应标题和 ℃/mm 单位、无匹配条件显示空结果提示，且无阻断流程的页面错误提示，即判定通过。
- NFR-K-02：页面以桌面演示为优先，不要求移动端适配或跨终端一致性。

## 5. 安全边界（NFR-S）

- NFR-S-01：验收时分别提交“开始时间晚于结束时间”的查询条件、缺少城市/模型/要素关联项的预报记录，以及非数值的 T2M 或 PRECIP 数值；每一种输入均应被阻止执行或保存，并显示对应的明确提示，且不得产生查询结果或新增/修改预报记录，即判定通过。
- NFR-S-02：本项目不实现登录、权限角色、JWT、Redis 或生产级安全体系，不将其作为验收项。

## 6. 可演示性（NFR-D）

- NFR-D-01：应准备覆盖 ECMWF、NOAA 与 T2M、PRECIP 的有限示例数据，使两种核心图表均可演示。
- NFR-D-02：演示可按“设置条件—查看表格—查看图表—维护基础资料”完成；不承诺高并发、高可用或生产级部署。
