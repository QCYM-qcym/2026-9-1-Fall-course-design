## 2. 功能组织

| 页面 | 用户目标 | 数据入口 |
| --- | --- | --- |
| /weather（/ 重定向） | 查看山东 16 市分布，切换要素、模型、时间，点击详情 | workbench |
| /analysis | 查看指定城市、模型的温度/降水趋势及四项统计 | trend |
| /comparison | 比较指定城市、要素的 ECMWF / NOAA 结果 | comparison |
| /management | 一个 Tabs 页面维护四类对象 | 16 个 CRUD API |

四类筛选维度仍为城市、模型、要素、时间范围，但不是每个页面都强制传全部维度：工作台查全省不传 cityId；趋势固定双要素不传 elementId；对比固定双模型不传 modelId；管理允许可选筛选。

## 3. 核心闭环

默认 ECMWF + T2M + 约 7 天演示窗口 → 一次取得所有城市所有时刻 → 前端缓存 → 时间轴本地切换 → 城市详情 → 趋势 → 模型对比 → 维护记录 → 缓存失效 → 重新查询确认图表与表格更新。

## 4. 数据与质量

四张 3NF 核心表不变。16 市、2 模型、2 要素、3 小时粒度 56 时次，计划约 3584 条记录。数据为离线整理或明确标注的演示数据，不声称实时真实预报。缺测显示缺失而非补零，降水累计只对同一统计窗口内非重叠时段值求和。

## 5. 范围与验收

山东地图升级为 P0，完整 CRUD 已由用户确认，不再待定。保留简单分层，排除登录、Redis、在线气象处理、复杂 GIS、模型评分和训练。中检与最终验收分层推进，详见下列唯一有效依据。

## 7. 系统边界

山东地图为增强功能；登录权限、JWT、Redis、Docker、微服务、TDengine、NetCDF 在线解析、ERA5、Pressure Level、RMSE、多模式演变矩阵、复杂风场、30 天延伸期、Python 服务、K8s 与生产级部署均不在范围内，详见 [[06-系统边界与不做事项|系统边界与不做事项]]。

## 8. 用例分析

用户可设置查询条件、查看表格、切换温度/降水图表，并进行四类基础资料管理。用例边界见 [[07-用例说明|用例说明]] 与 [[09-白板/02-系统用例图.canvas|系统用例图]]。

## 9. 业务流程

用户选择城市、日期/时间范围、要素和模型，系统校验条件后读取匹配预报记录，先以表格返回结果，再按数据类型展示温度折线或降水柱状图。流程细化将见 [[02-系统设计/03-业务流程设计|业务流程设计]]、[[09-白板/04-DFD-0层数据流图.canvas|DFD-0层数据流图]] 与 [[09-白板/08-核心查询泳道图.canvas|核心查询泳道图]]。

## 10. 验收目标

验收时应能说明三大模块、四类查询条件、两类核心要素、两种示例模型和四类管理数据之间的对应关系；能展示查询表格、温度折线和降水柱状图；地图若出现只能作为增强项。开发排期参见 [[06-项目管理/02-两周开发计划|两周开发计划]]，本系统设计输入参见 [[02-系统设计/01-总体架构设计|总体架构设计]]。
