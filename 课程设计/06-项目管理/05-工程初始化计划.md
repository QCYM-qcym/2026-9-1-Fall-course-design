# 工程初始化计划

## 1. 计划状态

本文只规定下一阶段的工程初始化边界、目录职责和执行顺序，不表示 Spring Boot、Vue、MySQL 或任何业务功能已经创建、配置或运行。

## 2. 环境确认

工程初始化前由成员 A、成员 B 共同记录并确认以下环境：

- Java 8；
- Maven；
- Node.js 与 npm；
- MySQL 8.0.16+；
- Chrome 与 Microsoft Edge。

环境确认只记录实际版本和可用性，不在当前文档阶段下载依赖或创建工程。

## 3. 后端初始化规划

后端计划采用 Java 8、Spring Boot 2.7.18、Maven、MyBatis-Plus 和 MySQL 驱动。包边界规划如下：

| 包 | 计划职责 |
| --- | --- |
| `controller` | 接收 REST 请求、完成基础格式检查并组织响应。 |
| `service` | 处理查询组合、关联校验、要素数值范围和业务唯一键规则。 |
| `mapper` | 使用 MyBatis-Plus 访问四张核心表。 |
| `entity` | 映射 `city`、`forecast_model`、`weather_element`、`forecast_record`。 |
| `dto` | 承载查询条件及新增、修改请求数据。 |
| `vo` | 承载供表格和图表共同使用的查询结果。 |
| `config` | 放置跨域、MyBatis-Plus 等必要配置。 |
| `exception` | 统一表达参数、关联、重复数据和持久化异常。 |

Controller 不直接访问 Mapper；业务校验集中在 Service；Mapper 不组织页面展示数据。

## 4. 前端初始化规划

前端计划采用 Vue 3、Vite、JavaScript、Element Plus、ECharts、Axios 和 Vue Router。目录边界规划如下：

| 目录 | 计划职责 |
| --- | --- |
| `views` | 查询页和基础数据管理页面。 |
| `components` | 查询条件、结果表格及图表等可复用组件。 |
| `api` | 封装查询与四类数据管理请求。 |
| `router` | 配置查询页和管理页路由。 |
| `utils` | 放置时间、单位和错误提示等通用处理。 |

表格与 ECharts 必须消费同一轮查询结果，不在不同组件中重复请求数据。

## 5. 初始化顺序

1. 确认 Java、Maven、Node.js、npm 和 MySQL 的实际版本。
2. 最终复核 [[03-数据库设计/08-SQL设计说明|SQL设计说明]]，确认 DDL 尚未执行且可以进入实施。
3. 初始化 Spring Boot 后端工程。
4. 配置 MySQL 连接与 MyBatis-Plus。
5. 初始化 Vue 3 + Vite 前端工程。
6. 配置 Vue Router、Axios 和 Element Plus。
7. 建立查询与四类管理对象的基础 REST API 契约。
8. 准备覆盖济南、青岛、烟台、潍坊、临沂、济宁、ECMWF、NOAA、T2M、PRECIP 的约 7 天演示数据。
9. 开始实现“条件提交—数据库查询—表格—对应图表”的核心查询链路。

上述步骤属于下一阶段执行顺序，本轮不执行其中任何工程创建、依赖安装、建库或编码操作。

## 6. 初始化完成判定

工程初始化阶段完成时应能提供：环境版本记录、前后端工程目录、数据库连接配置说明、已评审的 API 契约、DDL 执行与结构检查记录、演示数据说明及核心查询链路开发待办。只有届时实际产生并验证的成果才能标记为完成。

## 7. 范围与风险控制

- 不在初始化阶段引入登录、权限、Redis、微服务、TDengine、ERA5 或生产部署。
- 不改变四张核心表、业务唯一键、三大模块和冻结技术栈。
- 数据库或接口字段若需调整，先按 [[01-立项与需求/09-需求冻结确认|需求冻结确认]] 的变更规则记录影响。
- 初始化失败时保留错误信息，先确认版本和配置，不以扩大技术栈作为默认解决方案。
