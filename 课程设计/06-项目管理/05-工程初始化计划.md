# 工程初始化计划 V2

> DOC-V2-INIT-PLAN：按 SYSTEM-DESIGN-V2 修订。本文只规划 PROJECT-INIT-1 及后续顺序，不表示任何工程、数据库、API 或测试已经完成。本轮只维护文档。

## 1. 目标

在 V2 设计基线上建立可启动、可构建、可测试的最小前后端工程骨架，明确数据库脚本和版本档案的位置；不在初始化阶段实现业务功能。

最终产品范围保持 Weather Workbench、Trend Analysis、Model Comparison、Data Management 四页面，山东地图 P0、全部 16 地级市、19 个 REST API。初始化完成不等于上述产品功能完成。

## 4. Frontend 初始化

### 技术栈

Vue 3 + Vite + JavaScript + Element Plus + ECharts + Axios + Vue Router。状态优先用 Vue Composition API、组件 props/emits 和少量模块内状态。

初始化不使用 TypeScript、Pinia、Tailwind、Bootstrap、Leaflet、Mapbox、Cesium、复杂状态管理或 UI 动画库。Pinia 只有后续实现确有必要且另获确认后才评估，不作为预装依赖。

### 目录

```text
frontend/
├── package.json
├── vite.config.js
├── index.html
└── src/
    ├── api/
    │   ├── city.js
    │   ├── forecastModel.js
    │   ├── weatherElement.js
    │   ├── forecastRecord.js
    │   └── weather.js
    ├── assets/
    │   └── maps/
    ├── components/
    │   ├── common/
    │   └── weather/
    ├── router/
    │   └── index.js
    ├── views/
    │   ├── WeatherWorkbench.vue
    │   ├── TrendAnalysis.vue
    │   ├── ModelComparison.vue
    │   └── DataManagement.vue
    ├── utils/
    ├── App.vue
    └── main.js
```

api/ 为四类管理对象及 weather 展示请求保留入口；初始化只准备模块位置和 Axios 基础接入，不实现业务请求及数据处理。

### Router

| 路由 | 页面 | 初始化范围 |
| --- | --- | --- |
| / | 重定向 /weather | 不另建首页 |
| /weather | WeatherWorkbench.vue | 最小工作台路由骨架 |
| /analysis | TrendAnalysis.vue | 最小趋势路由骨架 |
| /comparison | ModelComparison.vue | 最小模型比较路由骨架 |
| /management | DataManagement.vue | 最小管理路由骨架，后续为四 Tab |

不新增登录页、404 页面、设置中心、用户中心或首页 Dashboard。

### Workbench 边界与 UI 基线

components/weather/ 和工作台页面预留承载 WeatherToolbar、LayerSwitcher、ModelSwitcher、ShandongWeatherMap、WeatherLegend、CityDetailPanel、ForecastTimeline 的位置；这些是后续组件，不要求初始化就生成完整组件实现。

初始化只建立深色现代工作台的最小全局样式：页面背景、基础文字色、卡片背景、基础间距、CSS reset、全屏布局。最终 Windy 风格视觉及交互在后续 FE 阶段完成，不复制 Windy 的代码或专有资产。

PROJECT-INIT-1 不实现地图、时间轴、城市详情、图层/模型业务切换或缓存，不下载 GeoJSON。

### 初始化验收

Vue 工程可启动；四路由能跳转，根路径重定向正确；Element Plus 可用；ECharts 可模块化导入；Axios 可用且 API 层位置明确。四页只保留最小骨架，构建按真实 package.json script 验证，不把占位内容写成业务完成。

## 5. Backend 初始化

### 技术栈

Java 8 + Spring Boot 2.7.18 + Maven + MyBatis-Plus + MyBatis XML + MySQL Connector + Bean Validation；测试采用 JUnit 5 / Spring Boot Test。

不加入 Spring Security、Redis、JPA、MapStruct、Docker、Flyway、Liquibase 或 DDD。没有团队明确决定时不使用 Lombok；Swagger/OpenAPI 需后续单独批准，不预装。

### 包结构

```text
backend/
├── pom.xml
└── src/
    ├── main/
    │   ├── java/<base-package>/
    │   │   ├── WeatherApplication.java
    │   │   ├── common/
    │   │   │   ├── ApiResponse.java
    │   │   │   ├── BusinessException.java
    │   │   │   └── GlobalExceptionHandler.java
    │   │   ├── config/
    │   │   │   └── CorsConfig.java
    │   │   ├── controller/
    │   │   ├── dto/
    │   │   ├── entity/
    │   │   ├── mapper/
    │   │   ├── service/
    │   │   └── vo/
    │   └── resources/
    │       ├── application.yml
    │       └── mapper/
    └── test/
        └── java/
```

这是候选目标结构；公共响应、异常、跨域类仅准备位置或必要可编译骨架，完整公共行为在 BACKEND-BASE-1 落实，不把空壳认定为已实现。空目录的留存方式在实际初始化时确认，不为留目录创建伪业务类。

最终分层保持 Controller → Service → Mapper → MySQL；Controller 不直接访问 Mapper。五 Controller、五 Service、四 Mapper 的业务实现仍在后续版本：

- 四类 CRUD 使用 MyBatis-Plus BaseMapper。
- WeatherQueryController → WeatherQueryService 复用 ForecastRecordMapper，不另增 WeatherQueryMapper。
- ForecastRecordMapper.xml 承担 selectWorkbenchData、selectTrendData、selectComparisonData；管理明细 JOIN 可同处处理。
- 19 API 是 16 个 CRUD 加 GET /api/weather/workbench、GET /api/weather/trend、GET /api/weather/comparison。本阶段不实现任何一个业务 API。

### 配置

MyBatis-Plus 配置与 XML 资源位置应可加载；数据库连接信息外部化，概念变量为 DB_HOST、DB_PORT、DB_NAME、DB_USERNAME、DB_PASSWORD，具体命名在 PROJECT-INIT-1 统一。

application.yml 只能含安全默认值或环境变量引用，不提交真实密码、令牌或本机私有路径；密码不提供真实默认值。跨域只准备必要配置位置，实际前端来源在初始化时确认。

### 测试与初始化验收

保证 Spring Boot 可启动、基础包结构存在、MyBatis-Plus 依赖与配置可加载、测试框架可运行；执行 Maven 构建及 `mvn test`，其中至少一项实际加载 Spring Context，而非只有空测试。

初始化不隐式创建 MySQL 实例或四表。启动/Context 测试的数据源前提须在 PROJECT-INIT-1 记录：使用用户授权的现有开发实例和外部配置；若实例不可用，如实记录阻塞，不生成数据库、不跳过必要配置验证后声称全部通过。若采用不访问业务表的启动验证，也须说明没有验证真实数据库连通性。

不得实现 CityController、WeatherQueryController、业务 Service、业务 Mapper SQL 或 19 个 API；这些归后续功能任务。

## 6. Database 初始化

### 文件结构

```text
database/
├── schema.sql
├── data.sql
└── README.md
```

PROJECT-INIT-1 只建立文件骨架和说明，不执行 DDL，不自动建库或导入数据。

### 数据库版本与后续职责

MySQL 8.0.16+；后续 DB-INIT-1 经审查和授权后将冻结 DDL 落入 schema.sql，包括四表、主键、外键、唯一约束、坐标 CHECK 和索引：

- city、forecast_model、weather_element、forecast_record，不新增业务表。
- 业务唯一键：(city_id, model_id, element_id, forecast_time)。
- forecast_record 除主键外只保留业务唯一索引、(model_id, element_id, forecast_time) 工作台联合索引、element_id 单列索引；不重复保留旧 model_id 单列索引。

data.sql 后续负责山东 16 市、ECMWF/NOAA、T2M/PRECIP 与课程演示 forecast 数据。城市为济南、青岛、淄博、枣庄、东营、烟台、潍坊、济宁、泰安、威海、日照、临沂、德州、聊城、滨州、菏泽；编码依 SQL 设计说明，核心演示济南/青岛。

16×2×2×56=3584 条只是约 7 天、3 小时粒度的规划规模；初始化阶段不得未经审查批量生成正式数据。后续为中检准备必要的可核对演示记录，明确来源/许可或合成标记、时间窗口、单位及 PRECIP 非重叠 3 小时时段量含义。缺测不补零，不将合成数据声称为真实 ECMWF/NOAA 预报。

README 记录 MySQL 版本、初始化顺序、数据规模、数据来源和导入方法；骨架阶段未实现内容明确标为待执行。后续顺序为 city → forecast_model → weather_element → forecast_record。

### 安全配置与初始化验收

仅记录环境变量用法和无秘密的操作说明；不得暴露真实 MySQL 密码。验收仅确认三个文件骨架存在、职责和未执行状态明确、未批量生成 forecast 数据；不声称数据库结构已创建或约束已实测。

## 8. 前后端协作方式

成员 A 主责数据库、后端和 Workbench API；成员 B 主责 Vue、地图与 Workbench UI。两人共同参与契约核对、联调和测试，不长期完全隔离。

API V2 已冻结，前后端可以并行：Frontend Mock → Backend 实现 → Axios 联调。每完成一个核心 API 就尽快联调，不等后端 19 个接口全部完成才接入。

Mock JSON 必须严格匹配 [API V2](../02-系统设计/04-接口设计.md) 的真实 Response。例如 Workbench 使用 code/message/data 包装及 model、element、times、records；不得另造字段或单城市接口。由 Mock 切换到 Axios 只替换数据来源，Mock 不能充当中检真实链路证据。

Workbench 后续使用批量加载 + 前端内存缓存；key 为 modelId、elementId、startTime、endTime 的规范化元组，最近最多 8 个组合。时间轴本地过滤，不重新请求；CRUD 成功清缓存并废弃旧请求，手动刷新可绕过缓存；不使用 Redis。Trend/Comparison 每次提交或进入重新查询。本节只记录后续职责，PROJECT-INIT-1 不实现缓存和业务 Mock。
