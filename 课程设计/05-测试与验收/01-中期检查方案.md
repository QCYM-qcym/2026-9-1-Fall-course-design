## 1. 状态与目标

计划日期 2026-09-11，成员 A/B 共同演示。当前仅方案，检查尚未执行，不填“通过”。中检不要求全部 V2 完成，目标是在约两周开发节奏内先证明山东地图主链路可运行。

## 2. 最低可演示清单

| 检查项 | 最低通过条件 | 证据（后续填写） |
| --- | --- | --- |
| 山东地图 | ECharts Map + GeoJSON 可显示全部 16 地级市，非空白占位图 | 地图截图、资源来源/许可 |
| 城市与四表 | 16 市基础数据存在，city/model/element/record 四表及约束可说明 | 四表结构、城市记录 |
| 工作台接口 | GET /api/weather/workbench 可用，ECMWF + T2M，返回整个范围全省数据 | Postman/Apifox 响应 |
| 时间轴 | 至少多个时刻可切换，地图值与颜色同步 | 连续操作与 Network 记录 |
| 城市详情 | 点击济南显示名称、模型、时间、温度、单位 | 页面截图 |
| 一个趋势图 | 从详情进入趋势页面，可显示一条真实查询响应驱动的 T2M 趋势 | trend 响应、折线图 |
| 开发过程 | Git 有两名成员真实开发与合并记录，不伪造贡献 | 实际 log/分支记录 |
| 当前进度 | 明确已实现/未完成/风险，不把完整 V2 写成中检已完成 | 阶段 README |

中检的一个趋势图只是前端最低展示；trend 若已实现应遵守 V2 双序列与统计契约，未完成项在阶段记录说明，不另造不兼容临时接口。

## 3. 建议演示顺序

打开 / → /weather 默认 ECMWF/T2M → 全省地图 → 点击济南 → 拖动多个时刻并观察值变化、确认无新增 API → 详情“查看趋势” → 一条温度折线 → 说明四表与唯一键 → 展示真实 Git 记录 → 报告中检后补齐项。

## 4. 分阶段安排与风险

- 中检前优先地图资源/16 市映射、四表/演示数据、workbench、时间轴、详情和一个趋势图。
- 中检后补齐 Trend 双图四统计、Comparison、完整 CRUD、异常/缺测/缓存失效与 GUI 打磨，再做最终测试。
- 完整 CRUD 与 Comparison 不作为本次中检最低通过条件，但仍是最终 P0 范围，不得默默取消。
- 若地图来源、数据准备或主链路延误，当日记录实际阻塞、责任人、修复时间与影响，向用户说明，不临时引入 GIS 平台或在线数据链路。

## 5. 记录方式

执行时逐项填写“通过/未通过/未运行”、环境、数据批次与范围、证据链接、问题与责任人。尚未执行项目均标“未运行”。阶段档案只保存说明/截图/测试和真实 Git 信息，不复制工程；本轮不创建中检源码版本、不提交。
