# 总体架构设计 V2

## 1. 定位与技术栈

两人、约两周，采用 Monorepo 前后端分离、Spring Boot 单体和简单分层，不追求生产级扩展。工程、四页与 19 个业务 API 已完成阶段验收，归档至 v0.13；最终验证状态见 CURRENT_CONTEXT，本地开发配置不等于生产部署配置。

| 层次 | 冻结方案 |
| --- | --- |
| Frontend | Vue 3、Vite、JavaScript、Element Plus、ECharts、Axios、Vue Router |
| Backend | Java 17、Spring Boot 2.7.18、MyBatis-Plus、MyBatis XML、Maven 3.9.16 |
| Database | MySQL 8.0.16+，仅四表 |
| Testing | JUnit 5、Spring Boot Test、Postman / Apifox |

调用链：Vue → Axios REST JSON → Controller → Service → Mapper → MySQL。前端不直连数据库，Controller 不直接访问 Mapper。

## 2. 后端职责

| 接口领域 | Controller | Service | Mapper |
| --- | --- | --- | --- |
| 城市 CRUD | CityController | CityService | CityMapper |
| 模型 CRUD | ForecastModelController | ForecastModelService | ForecastModelMapper |
| 要素 CRUD | WeatherElementController | WeatherElementService | WeatherElementMapper |
| 记录 CRUD / 全量列表 | ForecastRecordController | ForecastRecordService | ForecastRecordMapper |
| workbench / trend / comparison | WeatherQueryController | WeatherQueryService | 复用 ForecastRecordMapper |

总计五个业务 Controller、五 Service、四 Mapper、四 Entity；另有不计入 19 业务 API 的健康检查。基础 CRUD 用 BaseMapper；管理记录 GET 用 selectList 全量 id ASC，再按去重 ID 批量读取三类字典组装扩展 VO，使用只读一致性事务，不逐行查库、不增加 Mapper 或筛选接口。

展示查询在 ForecastRecordMapper.xml 实现 selectWorkbenchData、selectTrendData、selectComparisonData。XML 使用绑定参数、JOIN、WHERE、ORDER BY，便于解释关系查询、索引和稳定排序；不通过控制器循环查库或把关联名称冗余入表。

WeatherQueryService 验证参数和关联、组织查询、分组 VO；trend 以 BigDecimal 计算温度 max/min/avg 与降水 total，平均值 HALF_UP 保留两位，空序列统计为 null。不存在 statistics 表或预计算任务。

## 3. 最小公共能力

公共能力为 ApiResponse<T>、BusinessException、GlobalExceptionHandler 和 ManagementValidation 等最小校验；Controller 做请求格式校验，Service 做业务校验；异常统一映射真实 HTTP 400/404/409/500，数据库唯一和外键约束兜底并发冲突。单次写操作为事务，失败不留半成品。当前本地前端通过 Vite /api 代理访问后端，未实现早期候选 CorsConfig；不据此声称生产部署已配置。

不加 Security、Redis、缓存框架、复杂日志、审计、DDD、Domain Service、Repository Interface/Impl 等层。

## 4. 当前后端主要目录

```text
backend/
├── pom.xml
└── src/main/
    ├── java/com/shandong/weather/
    │   ├── WeatherApplication.java
    │   ├── common/
    │   │   ├── ApiResponse.java
    │   │   ├── BusinessException.java
    │   │   └── GlobalExceptionHandler.java
    │   ├── controller/
    │   │   ├── CityController.java
    │   │   ├── ForecastModelController.java
    │   │   ├── WeatherElementController.java
    │   │   ├── ForecastRecordController.java
    │   │   └── WeatherQueryController.java
    │   ├── entity/       # City、ForecastModel、WeatherElement、ForecastRecord
    │   ├── mapper/       # 上述四个 Mapper
    │   ├── service/      # 上述五个 Service
    │   ├── dto/
    │   └── vo/
    └── resources/mapper/ForecastRecordMapper.xml
```

base package 为 com.shandong.weather；具体依赖以 backend/pom.xml、frontend/package.json 和锁文件为准，本轮不升级依赖或扩大技术栈。

## 5. 数据、前端与仓库边界

四表 city、forecast_model、weather_element、forecast_record 保持 3NF。山东 16 市、ECMWF/NOAA、T2M/PRECIP，实际为 192 条合成课程演示数据，约 3584 条仅为早期规划；不是实时气象服务。名称/单位用 JOIN，统计在 Service，无额外业务实体。

根级 frontend/ 最新 Vue，backend/ 最新 Spring Boot，database/ 最新 SQL；课程设计/ 是唯一当前文档；versions/ 保存阶段说明、测试结果、截图、Git 信息。禁止复制多套代码或重复建立 docs/ 体系。

地图只用 ECharts + 静态 frontend/src/assets/maps/shandong.json，来源与许可见 v0.7。工作台内存缓存归前端页面实例，卸载即清空，不引入后端缓存。
