# 接口设计 V2.0

> AUTH-ROLE-1：原十九个气象业务API保持，另计GET auth/csrf、POST auth/login、POST auth/logout、GET auth/me四认证接口及health辅助接口。采用Session/BCrypt/CSRF；USER允许三字典与三展示GET，ADMIN才可记录GET与所有管理写入。401/403及完整认证契约见[认证说明](../docs/AUTH-ROLE-1.md)。

> MONTHLY-SYNTHETIC-DATA-1 当前扩展：Workbench与Comparison允许T2M、PRECIP、TCC、WIND_SPEED_100M、WIND_DIR_100M、RH六要素；按真实字典ID查询，响应形状不变。Trend仍固定T2M/PRECIP与四项统计，管理记录仍全量id ASC。十九业务API不增加。下文两要素样例是v1.0兼容样例，不是新数据范围上限；完整范围与Runtime状态见 [月级数据说明](../docs/MONTHLY-SYNTHETIC-DATA-1.md)。

> 设计冻结日期：2026-09-06。十九个业务接口现已实现；SYSTEM-FINALIZE-1 按后续已批准的 CRUD 全量 GET 与前端图表方案同步当前说明，不改变接口实现。V1 阶段记录保留在 [v0.2-api-contract](../../versions/v0.2-api-contract/README.md)，最终验证见 [CURRENT_CONTEXT](../docs/context/CURRENT_CONTEXT.md)。

## 1. V1.0 → V2.0 变化

V1 为 7 个核心 API（三字典 GET + 四记录 CRUD），字典完整 CRUD 与 FR-M-01～03 存在待确认冲突。V2 正式补齐 9 个字典写接口，增加 workbench、trend、comparison 三个展示查询，共 19 个。原因是地图主工作台、趋势分析和模型对比的产品升级，不是引入新业务领域。

其中 12 个基础字典 CRUD 与 4 个记录 CRUD 大量复用标准逻辑，真正核心业务查询只有三个。FR-M-01～03 已确认完整 CRUD，不再待定。记录 GET 按 BE-MANAGEMENT-CRUD-1 批准范围全量返回、id ASC，不实现筛选或分页；工作台批量返回全省全部时刻，趋势一次返回双要素，比较一次返回双模型。V1 人为温度 -80～60 与降水 1000 上限取消，按本节后的 V2 校验执行。

## 2. 通用约定

- Base URL：/api；JSON UTF-8；字段 camelCase。新增独立认证接口；无服务端分页、GET /{id}、导出或额外统计接口。
- GET 使用 query 参数；POST / PUT 使用 application/json，PUT 为完整替换可编辑字段，路径 id 为目标，不接收 body.id。DELETE 无请求体。
- 成功全部 HTTP 200，包装 {code:200,message:"success",data:...}。POST/PUT 返回保存后的完整 VO；DELETE 返回 data:null。
- 错误包装 {code:400|401|403|404|409|500,message:"可理解的原因",data:null}，真实 HTTP 状态必须与 code 一致，不用 HTTP 200 包装错误。认证/安全拒绝使用JSON，不重定向API到HTML。
- 列表无结果返回 data:[]，展示查询返回其结构中的空数组。资源存在但无记录不是 404。
- ID 在 JSON 中为正整数 number，课程系统 API 接受 1～9007199254740991，避免 JavaScript 精度损失；数据库 BIGINT UNSIGNED 类型不变。未来导入/生成 id 也需满足该 API 范围，不把 BIGINT 全域直接暴露给 JS。
- 金额无关：value / 坐标 / 统计是 JSON number，后端值与统计使用 BigDecimal；显示可补小数位但不更改含义。

### 时间

时间格式严格 yyyy-MM-dd HH:mm:ss，统一 Asia/Shanghai 本地业务时间；无 Z/偏移、不转换成 UTC，不接受非法日期。起止都出现且 startTime ≤ endTime，查询闭区间，startTime=endTime 合法；数据库 DATETIME 为有效时刻。GET 时间经 URL 编码，不能发浏览器 Date 默认字符串。

管理 GET 不接收筛选条件；三个展示接口时间范围必填。为空字符串不等于省略，返回 400。

### 错误语义

| HTTP / code | 场景 |
| --- | --- |
| 400 | 缺少必填、类型/日期非法、时间单边或倒置、非法数值/长度/单位、展示不支持的模型或要素 |
| 404 | PUT/DELETE 目标不存在；请求指定的 city/model/element 关联不存在 |
| 409 | 唯一编码冲突、预报业务键重复、删除被引用字典、修改已引用字典的业务含义 |
| 500 | 未预期服务端异常或核心演示字典配置缺失；不暴露 SQL、密码或异常栈 |

校验顺序：格式与值（400）→ 目标/关联存在（404）→ 业务限制/冲突（400/409）→ 执行；数据库竞争条件仍由唯一/外键约束兜底，映射对应冲突，不返回原始异常。

## 4. 字典写入与返回结构

| DTO | 字段 | 规则 |
| --- | --- | --- |
| CityWrite | cityCode、cityName、longitude、latitude | 全必填；编码最长32，名称50；经度 -180～180、纬度 -90～90，有限且最多6位小数 |
| ForecastModelWrite | modelCode、modelName、description | 前两者必填，最长32/50；description 可省略/null，最长255；PUT 省略视为 null |
| WeatherElementWrite | elementCode、elementName、unit | 全必填，最长32/50/16 |

编码使用大写英文字母、数字或下划线，非空；名称与单位 trim 后非空，编码唯一。字典 VO 等于上述字段加 id；description 始终返回 string 或 null。不新增要素 description 或更新时间字段。

示例（POST /api/cities 请求体，数值仅用于契约说明）：

```json
{"cityCode":"JINAN","cityName":"济南","longitude":116.98,"latitude":36.67}
```

成功 data 示例：

```json
{"id":1,"cityCode":"JINAN","cityName":"济南","longitude":116.98,"latitude":36.67}
```

模型请求示例 {"modelCode":"ECMWF","modelName":"ECMWF","description":null}；
要素请求示例 {"elementCode":"T2M","elementName":"2 米气温","unit":"℃"}。这些示例不是本轮实际写入。

### 核心字典与 CRUD 边界

核心演示仍只使用山东 16 市、ECMWF/NOAA、T2M/PRECIP；完整字典 CRUD 可用临时未引用数据演示，但不因此扩展核心气象展示支持范围。选择器按核心编码筛选，地图按 16 个稳定 cityCode 识别，数据库名称使用短名，通过前端映射适配 GeoJSON 全名。

已被记录引用的 cityCode、modelCode、elementCode 或 unit 不能改变含义，变更返回 409；名称、模型 description、合法城市坐标可更新。核心 T2M 单位必须 ℃、PRECIP 必须 mm，错误返回 400。删除任何被引用字典返回 409，绝不级联删记录。未引用的临时对象可正常改删。核心字典若被人为删除，页面明确报配置/选择错误，不伪造缺失字典。管理演示不破坏冻结的核心集合。

## 5. 预报记录 CRUD

### 写入 DTO

```json
{"cityId":1,"modelId":1,"elementId":1,"forecastTime":"2026-09-06 08:00:00","value":28.6}
```

五字段全部必填；三个关联必须存在。value 为有限 JSON 数值，DECIMAL(10,2)，最多两位小数且绝对值 ≤ 99999999.99；超出拒绝 400，不静默截断。PRECIP value≥0；T2M 不人为设严格气象范围。核心演示仅为两要素，其他临时字典不进入展示查询。

唯一键 (cityId,modelId,elementId,forecastTime) 重复返回 409。PUT 按路径记录 id 定位，可改五字段，判重排除本记录；不存在返回 404。DELETE 不存在同样 404，不以成功掩盖过期列表。

### 管理 GET

无筛选参数，全量返回，按 id ASC，规模小不分页。此前组合筛选规划不属于本次批准实现，不据此扩展接口。

### ForecastRecordVO（GET 数组及 POST/PUT 对象）

```json
{
  "id":1,
  "cityId":1,"cityCode":"JINAN","cityName":"济南",
  "modelId":1,"modelCode":"ECMWF","modelName":"ECMWF",
  "elementId":1,"elementCode":"T2M","elementName":"2 米气温","unit":"℃",
  "forecastTime":"2026-09-06 08:00:00","value":28.6
}
```

编码、名称、单位是关联字典的 VO 字段，不得添加到 forecast_record 表。当前管理列表先读取记录，再按去重 ID 批量查询字典组装 VO；基础写入用 BaseMapper，展示查询 JOIN 继续由同一 ForecastRecordMapper.xml 完成。

## 6. 核心展示：GET /api/weather/workbench

modelId、elementId、startTime、endTime 全必填；不传 cityId。modelId 对应 ECMWF 或 NOAA，elementId 对应 T2M 或 PRECIP；合法存在但非核心字典返回 400。一次查询全部山东 16 市在完整范围内的现有记录，不按 selectedTime 请求。

```json
{
  "code":200,"message":"success",
  "data":{
    "model":{"id":1,"modelCode":"ECMWF","modelName":"ECMWF"},
    "element":{"id":1,"elementCode":"T2M","elementName":"2 米气温","unit":"℃"},
    "times":["2026-09-06 08:00:00","2026-09-06 11:00:00"],
    "records":[
      {"cityId":1,"cityName":"济南","forecastTime":"2026-09-06 08:00:00","value":28.6},
      {"cityId":1,"cityName":"济南","forecastTime":"2026-09-06 11:00:00","value":29.1}
    ]
  }
}
```

这是两点结构示例，不表示初始化只有济南。times 为 records 有效时间去重后严格升序；records 按 forecastTime、cityId 稳定排序。model/element 对象为请求关联的真实字典元数据；无匹配仍保留元数据，times:[]、records:[]。

响应驱动地图、时间轴、图例、城市详情。城市编码/坐标由先前城市字典取得；静态地图保留无值行政区。山东范围以数据需求中的 16 个 cityCode 固定集合过滤，不因为新增临时城市而扩展到外省。

缓存键 modelId + elementId + startTime + endTime；拖动时间轴只本地过滤，不发 API。缓存限工作台实例，离页即清空并废弃旧请求，无 KeepAlive；管理写入后重新进入展示页会重新读取字典和数据。无后端缓存或工作台独立强制刷新按钮。

## 7. 核心展示：GET /api/weather/trend

cityId、modelId、startTime、endTime 全必填；不接收 elementId 来切成单要素。城市为山东核心城市，模型 ECMWF/NOAA；存在但不支持返回 400。一次查询 T2M 和 PRECIP，Service 分组及计算。

```json
{
  "code":200,"message":"success",
  "data":{
    "cityId":1,"cityName":"济南",
    "modelId":1,"modelName":"ECMWF",
    "temperature":[
      {"forecastTime":"2026-09-06 08:00:00","value":28.6},
      {"forecastTime":"2026-09-06 11:00:00","value":29.1}
    ],
    "precipitation":[
      {"forecastTime":"2026-09-06 08:00:00","value":0},
      {"forecastTime":"2026-09-06 11:00:00","value":1.2}
    ],
    "statistics":{
      "temperatureMax":29.1,
      "temperatureMin":28.6,
      "temperatureAvg":28.85,
      "precipitationTotal":1.2
    }
  }
}
```

temperature 对应固定 T2M/℃，precipitation 对应固定 PRECIP/mm，单位来自已校验的核心字典；前端共享字典按 elementCode 获取，不另加数据库字段。序列分别按 forecastTime 升序，不补齐缺测，单点唯一。

最高/最低/平均温基于实际温度样本，平均按 BigDecimal HALF_UP 两位；累计降水基于选中有效时刻对应的前 3 小时非重叠时段量求和。不可直接相加模式起报累计值。无温度记录则三个温度统计 null；无降水记录则 precipitationTotal:null，真实零降水统计为 0。双方都空仍返回城市/模型、空数组及四个 null。

前端两图与四统计卡消费此同次响应，无明细表；两序列独立处理，不按下标对齐，不补零。统计仅基于返回样本，null 统计显示 --。固定核心要素字典缺失属于初始化配置错误 500，不冒充无匹配。

## 8. 核心展示：GET /api/weather/comparison

cityId、elementId、startTime、endTime 全必填；不传 modelId。城市与要素限制同上述核心范围，同时查询 ECMWF、NOAA，固定按该顺序返回两个模型系列。

```json
{
  "code":200,"message":"success",
  "data":{
    "cityId":1,"cityName":"济南",
    "element":{"id":1,"elementCode":"T2M","elementName":"2 米气温","unit":"℃"},
    "series":[
      {"modelId":1,"modelCode":"ECMWF","modelName":"ECMWF","values":[{"forecastTime":"2026-09-06 08:00:00","value":28.6}]},
      {"modelId":2,"modelCode":"NOAA","modelName":"NOAA","values":[]}
    ]
  }
}
```

values 各自按 forecastTime 升序；模型存在但无记录仍保留空 values。都无结果仍保留两个系列。核心模型字典缺失为配置错误 500。前端时间并集升序对齐，缺值 null，不以 0 假造差异；T2M、PRECIP 均为双折线（FE-COMPARISON-1 已批准）。不返回 RMSE/MAE/bias/accuracy。

## 9. 后端查询与最小索引对应

三个查询归 WeatherQueryController → WeatherQueryService → ForecastRecordMapper.xml：
selectWorkbenchData / selectTrendData / selectComparisonData，使用 JOIN + WHERE + ORDER BY 和绑定参数，不拼 SQL。基础 CRUD 使用 MyBatis-Plus。

四表结构不变；预报记录仅业务唯一索引、工作台联合索引、要素外键单列索引三项二级索引，另有主键。详细 SQL 及取舍见数据库设计，不在 API 文档复制另一份 DDL。

## 10. 契约验收检查项

- 19 个方法/路径唯一，无新增单项 GET；四类 GET/POST/PUT/DELETE 成功结构完整。
- 错误 400/404/409/500 与 HTTP 一致；空匹配不报错；写入失败无数据变化。
- 记录 GET 全量 id ASC；展示查询单边时间 400、倒置 400、相等有效；重复记录 409、引用删除 409。
- Workbench times 去重升序、records 稳定排序，完整缓存后拖动 10 次无新增 API。
- trend 两要素与四统计核对，空序列 null，零降水 0，缺测不补零。
- comparison 双模型、时刻不齐/单模型空/全空均正确展示。
- 写记录后返回趋势得到新值；旧未完成请求不得回填过期工作台缓存。
- 阶段真实验收见 versions/v0.7～v0.13 对应记录；本轮整体验证与环境阻塞见 CURRENT_CONTEXT，不以检查项清单冒充运行证据。
