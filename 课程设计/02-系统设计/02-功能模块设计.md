## 3. 详情与跨页状态

详情只显示城市名称、当前模型、要素、预报时间、当前值、单位。“查看趋势”通过路由 query 传 cityId、modelId、startTime、endTime（时间 URL 编码）；/analysis 接收后校验，非法/已删除关联提示重新选择，不默默查询另一城市。即使当前时刻缺值，合法城市仍可查看范围趋势。

## 4. 趋势分析

筛选城市、模型、时间范围；一次 trend 返回 temperature、precipitation、statistics。TemperatureChart 为温度折线、PrecipitationChart 为降水柱状，四卡片显示最高/最低/平均温、累计降水。同页明细表由两序列按时间并集合并，不另查记录接口。缺点使用 null / “—”，图表不连接缺失温度点，不填零。

统计仅覆盖返回样本。页面显示两序列实际点数，并注明“累计为所选时刻对应的非重叠时段降水量之和”；有缺测提示统计并非完整窗口，空序列统计为 null。初始可沿用工作台状态或选择济南/ECMWF/演示窗口。

## 5. 模型对比

筛选城市、要素、范围；ComparisonChart 仅使用 comparison 响应。T2M 双折线，PRECIP 分组柱状图；时间取两个模型样本并集升序，模型缺值为 null，空模型保留图例与暂无数据提示。不跨模型求平均，不做 RMSE、MAE、bias、accuracy。

## 6. 管理页面

一个 Element Plus Tabs：城市、预报模型、气象要素、预报记录。各 Tab 有列表、添加按钮、编辑对话框和删除确认，前三类复用简单字典管理模式。记录表五参数可选组合，时间必须成对。编辑表单直接使用列表字段，不新增 GET /{id}。

成功后刷新当前列表，清空工作台缓存和必要字典缓存；重新进入趋势/对比必取新数据。记录更新/删除按 id，409 提示冲突或引用阻止删除，400 定位非法参数，404 提示刷新列表。字典试验用临时数据，核心 16 市/两模型/两要素保留稳定含义，校验细则以 API 为准。

## 7. UI 风格与四类状态

深色现代气象工作台，半透明深色悬浮卡片、适量 backdrop blur、圆角 8～12px、统一控件高度与字体层级；图表背景简洁，少边框，状态动画 200～300ms。文字、图例和数值保持足够对比度，不以颜色作为唯一信息。禁用动画时仍可完整操作。

Windy 仅参考地图主视觉与悬浮控件、图层、模型、时间轴、图例、点击详情等产品交互思想；不复制 Logo、图片、图标资产、CSS、专有素材或页面代码。

| 状态 | 页面行为 |
| --- | --- |
| Loading | 地图/图表遮罩，提交按钮防重复，旧数据不被误认为新筛选结果 |
| Empty | 保留地图边界或图表容器，明确“无匹配数据”，禁用不可用操作 |
| Error | ElMessage + 可见重试入口；不把失败缓存成空结果 |
| Success | 写入确认后 ElMessage.success，刷新并使相关缓存失效 |
