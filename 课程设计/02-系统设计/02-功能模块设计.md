# 功能模块与前端设计 V2

## 1. 路由与页面

| 路由 | 已实现页面 | 核心功能与请求 |
| --- | --- | --- |
| / | 重定向 /weather | 不另建首页 |
| /weather | WeatherWorkbench.vue | 地图工作台，workbench 一次批量加载 |
| /analysis | TrendAnalysis.vue | 城市/模型/范围，trend 双要素、四统计 |
| /comparison | ModelComparison.vue | 城市/要素/范围，comparison 双模型 |
| /management | DataManagement.vue | 四个 Element Plus Tabs，四类完整 CRUD |

所有页面共用简洁导航，无登录页。默认项从字典编码查对应 id，不硬编码数据库 id。

## 2. 工作台布局

地图占据最大区域；顶部 WeatherToolbar 放时间范围，修改范围即查询，无独立查询/刷新按钮；左侧 LayerSwitcher 与 ModelSwitcher 悬浮，地图旁放 WeatherLegend，右侧 CityDetailPanel 可收起，底部 ForecastTimeline。1366×768 下控件不得遮挡时间轴或重要地图区域；ECharts 正确 resize/dispose。

| 组件 | 输入 / 职责 | 输出 |
| --- | --- | --- |
| WeatherToolbar | 当前时间范围 | 范围变更后加载 |
| LayerSwitcher | T2M / PRECIP 字典项 | elementId |
| ModelSwitcher | ECMWF / NOAA 字典项 | modelId |
| ShandongWeatherMap | 静态 GeoJSON、cityCode 映射、当前时刻记录 | cityId 点击事件 |
| WeatherLegend | 当前要素、单位、当前时刻有效数值 | visualMap 动态色标 |
| CityDetailPanel | city、model、element、selectedTime、value | 城市选择、详情显示与关闭 |
| ForecastTimeline | 升序 times、selectedTime | 本地更新时间，不触发查询 |

初始 ECMWF + T2M，集中 DEMO_RANGE 为 2026-09-07 08:00:00～14:00:00，不依赖系统当天。进入后先取得三类字典，筛选山东 16 市、ECMWF/NOAA、T2M/PRECIP；默认编码缺失时使用仍受支持的选项并警告，无可用项或 16 市映射不完整时显示错误，不伪造 id 或响应。

workbench 返回全省、选定模型/要素、范围内全部时刻；当前演示为 16×3=48 条/组合。times 是记录中有效时间的去重升序集合；缺失整个时刻不伪造样本。每次查询或缓存命中后 selectedTime 取首个可用值；空 times 禁用时间轴。

图例按当前时次有效值计算动态色阶，不承诺跨时刻同色等值。T2M 冷暖渐变、PRECIP 单向渐变且起点为零；常量序列给予最小可显示色阶跨度；无数据不用有效零值着色。地图全部 16 个行政区始终显示，无记录显示中性色、“暂无数据”。

city_name 使用数据库短名，GeoJSON 名称通过稳定 cityCode 前端静态映射关联，不直接用“济南=济南市”的字符串假设。China-GeoData / MIT、16 features 与 16 市匹配已核验，来源见 v0.7；不引入其他 GIS 框架。管理中添加的临时城市不自动产生山东行政区。

## 3. 详情与跨页状态

详情显示城市、当前模型、要素、预报时间、值、单位及坐标。四页通过主导航独立进入；无“查看趋势”路由传参功能。RouterView 无 KeepAlive，离开工作台会清缓存并作废旧请求；管理后重新进入展示页重新取字典和数据。

## 4. 趋势分析

筛选城市、模型、时间范围；一次 trend 返回 temperature、precipitation、statistics。复用 TrendChart 分别绘制温度折线与降水柱状，四卡片只读后端最高/最低/平均温、累计降水。无同页明细表；两序列独立处理，不按下标强制对齐，不填零。

统计仅覆盖返回样本，页面说明缺测不补零、各要素时次独立，null/undefined 统计显示 --，真实 0 保留。初始按编码选择济南/ECMWF 和集中演示范围，字典加载后自动查询一次；后续筛选仅点击查询才请求，无缓存。

## 5. 模型对比

筛选城市、要素、范围；ComparisonChart 仅使用 comparison 响应。按 FE-COMPARISON-1 批准方案，T2M 与 PRECIP 均为 ECMWF/NOAA 双折线；时间取两个模型样本并集升序，模型缺值为 null，真实 0 保留。初始济南/T2M/集中演示范围，自动查询一次；后续点击查询请求，无缓存。不跨模型求平均，不做 RMSE、MAE、bias、accuracy。

## 6. 管理页面

一个 Element Plus Tabs：城市、预报模型、气象要素、预报记录。各 Tab 有列表、添加按钮、编辑对话框和删除确认，按需加载。记录API仍全量id ASC、无后端分页/筛选；月级46,080条导致真实浏览器交互超时后，按用户批准例外仅记录表增加100条本地分页。编辑从列表建立独立Draft，保存失败不提前修改列表，不新增GET /{id}。

成功后刷新当前列表，清空工作台缓存和必要字典缓存；重新进入趋势/对比必取新数据。记录更新/删除按 id，409 提示冲突或引用阻止删除，400 定位非法参数，404 提示刷新列表。字典试验用临时数据，核心 16 市/两模型/两要素保留稳定含义，校验细则以 API 为准。

## 7. UI 风格与四类状态

深色现代气象工作台，半透明深色悬浮卡片、适量 backdrop blur、圆角 8～12px、统一控件高度与字体层级；图表背景简洁，少边框，状态动画 200～300ms。文字、图例和数值保持足够对比度，不以颜色作为唯一信息。禁用动画时仍可完整操作。

Windy 仅参考地图主视觉与悬浮控件、图层、模型、时间轴、图例、点击详情等产品交互思想；不复制 Logo、图片、图标资产、CSS、专有素材或页面代码。

| 状态 | 页面行为 |
| --- | --- |
| Loading | 地图/图表遮罩，提交按钮防重复，旧数据不被误认为新筛选结果 |
| Empty | 保留地图边界或图表容器，明确“无匹配数据”，禁用不可用操作 |
| Error | ElMessage + 可见重试入口；不把失败缓存成空结果 |
| Success | 写入确认后 ElMessage.success，刷新并使相关缓存失效 |
